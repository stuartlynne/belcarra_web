Protocols

Belcarra USBLAN for Windows supports a range of networking-over-USB protocols and recognizes the protocol offered by the attached device (NCM, EEM, ECM, RNDIS).

Networking over USB protocol comparisons

Networking-over-USB protocols allow a USB device to provide network access to a host, or to receive network access from a host, by transferring network frames over USB bulk endpoints.

The primary protocols covered in USBLAN deployments are:

  • Simple
  • CDC-ECM
  • CDC-EEM
  • CDC-NCM
  • RNDIS

Protocol details

Simple

The Simple configuration is a streamlined variant of CDC-ECM that removes the interrupt endpoint requirement and uses default data interface behavior. This avoids requiring a Set Interface request to enable data flow.

CDC-ECM

CDC-ECM is the earliest standardized networking-over-USB protocol. It uses notifications on an interrupt endpoint for network and speed changes and was designed around bandwidth behavior on older USB host environments.

CDC-EEM

CDC-EEM simplified control configuration and introduced the option to send multiple network frames within a single USB bulk transfer. Because EEM does not define expected transfer sizes, robust multi-frame support is implementation-dependent.

CDC-NCM

CDC-NCM is the logical successor to ECM. It retains ECM-style configuration and adds encapsulation for multi-frame USB transfers, plus additional device requests that allow hosts and devices to negotiate behavior such as transfer sizing and frame handling.

RNDIS

RNDIS uses Microsoft NDIS control semantics over encapsulated commands/responses and supports multi-frame operation in bulk transfers. Operational limits such as transfer sizes and frame counts are established during RNDIS initialization.

Multi-frame support

EEM, NCM, and RNDIS can aggregate multiple network frames into one USB bulk transfer. Aggregation can significantly improve throughput by amortizing USB and driver-level transfer overhead across more than one network frame.

In practice, multi-frame behavior needs tuning: too much aggregation can add latency because contained frames are only forwarded after the transfer is received. Runtime heuristics are typically used to optimize throughput while keeping latency bounded.

  • ECM transfer size behavior is fixed.
  • EEM does not prescribe fixed transfer sizes and must terminate transfers correctly with short packets.
  • NCM and RNDIS allow negotiated/configurable behavior during setup and control exchange.
